# E2 收尾实施计划

> 面向智能体执行者：必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，按任务逐项执行本计划。步骤使用复选框（`- [ ]`）跟踪。

目标：在 E2 配置中明确执行 A 股交易规则，保留带哈希的证据，并验证覆盖范围明确的规范晋升凭证，使 E2 活动可复现、可审计。

架构：复用现有 `portfolio-backtester` 市场规则和执行模拟 API。原始数据集和大型运行输出保留在 Git 之外，在工作区证据目录中提交精简且固定哈希的证据描述和规范凭证输入。晋升门禁继续采用失败即关闭策略，凭证可以是规范且完整的，同时仍报告 `pending` 或 `failed` 检查。

技术栈：Python、pytest、YAML/JSON、`portfolio-backtester` 执行模拟器，以及 `research_contracts` 资产和晋升校验器。

规格：`docs/runbooks/e2-evidence-campaign.md` 和 `docs/evidence/e2-execution-evidence-20260828.json`

## 全局约束

- E2 执行模拟必须明确启用 A 股规则：100 股整手、T+1、价格涨跌停和上市状态。
- 已启用规则缺少输入时必须失败关闭，不能静默停用规则。
- 原始数据集和大型生成输出必须留在 Git 之外。提交的证据必须包含哈希和安全相对路径。
- 规范晋升证据必须使用 `strategy_promotion_evidence.v2`，并如实记录待处理或失败检查。
- 不要修改无关的 `feat/factor-execution-followup-v2` worktree。
