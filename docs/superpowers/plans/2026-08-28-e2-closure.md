# E2 Closure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the E2 campaign reproducible and auditable by enforcing A-share execution rules in its configuration, preserving hashed evidence, and validating a canonical promotion receipt with explicit review coverage.

**Architecture:** Reuse the existing `portfolio-backtester` market-rule and execution-simulation APIs. Keep raw datasets and large run outputs outside Git, but commit a compact, hash-pinned evidence descriptor and canonical receipt inputs under the workspace evidence tree. The promotion gate remains fail-closed: a receipt can be canonical and complete while still reporting `pending` or `failed` checks.

**Tech Stack:** Python, pytest, YAML/JSON, `portfolio-backtester` execution simulator, `research_contracts` artifact and promotion validators.

**Spec:** `docs/runbooks/e2-evidence-campaign.md` and `docs/evidence/e2-execution-evidence-20260828.json`

## Global Constraints

- A-share rules must be explicitly enabled for the E2 execution simulation: round lot 100, T+1, price limits, and listing status.
- Missing enabled-rule inputs must fail closed rather than silently disabling the rule.
- Raw datasets and large generated outputs must remain outside Git; committed evidence must contain hashes and safe relative paths.
- Canonical promotion evidence must use `strategy_promotion_evidence.v2` and remain truthful about pending or failed checks.
- Do not alter the unrelated active `feat/factor-execution-followup-v2` worktree.
