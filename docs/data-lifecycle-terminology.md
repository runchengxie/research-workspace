# 数据、研究与代码目录术语规范

## 目标

统一数据资产、研究运行和源代码的目录术语，避免把目录名称直接当成删除权限。
本规范先统一语义，再逐步迁移历史路径。历史路径在迁移完成前继续通过 manifest、receipt、
current contract 和兼容链接维持可发现性。

## 数据生命周期

| 目录 | 语义 | 删除前必须确认 |
| --- | --- | --- |
| `raw/` | 原始或供应商原生数据 | 是否仍是重建其他资产的唯一来源 |
| `staging/` | 正在处理、尚未发布的数据 | campaign 是否终止，是否存在未完成 receipt |
| `published/` | 已通过质量校验、可供消费者读取的版本 | 是否被 current 或 rollback 引用 |
| `current/` | 当前正式版本的稳定入口或 alias | 不得直接删除或改写 |
| `rollback/` | 已验证的可回滚版本 | 是否仍满足回滚策略 |
| `archive/` | 已退出当前流程但仍需保留的数据 | 是否已过保留期且有可验证替代物 |
| `cache/` | 可由固定输入重新生成的中间结果 | 是否确实可重建，是否仍有运行占用 |

目录名称只表达默认生命周期语义，不授予删除权限。删除或移动前必须检查：

1. `manifest` 是否存在且内容完整；
2. `receipt` 是否为成功或明确终止状态；
3. 是否被 `current`、`latest`、rollback alias 或其他 contract 引用；
4. 是否有活动锁、进程或未结束 campaign；
5. 是否存在经过校验的 successor；
6. 是否记录了归档、迁移或删除凭证。

## 研究目录

| 目录 | 语义 |
| --- | --- |
| `experiments/` | 研究问题、假设和实验入口 |
| `runs/` | 某次具体实验或任务运行 |
| `features/` | 研究运行产生的特征结果 |
| `snapshots/` | 固定时点的数据或模型快照 |
| `reports/` | 面向人阅读的分析报告 |
| `receipts/` | 运行、校验、发布和数据来源凭证 |

`baseline` 表示被比较的参考方案，`challenger` 表示正在评估的新方案，`incumbent`
表示当前参考或线上方案。它们是研究角色，不是数据生命周期状态。

## 源代码目录

可复用代码放在 `src/`，仓库入口和运维脚本放在 `scripts/`，自动化测试放在 `tests/`，
架构、契约、研究过程和运行说明放在 `docs/`。一次性实验入口可以留在 `experiments/`，
但应调用 `src/` 中的稳定代码，不在实验目录中发展第二套公共库。

## 常用运行术语

- `manifest`：文件、版本、日期范围、schema 和校验信息的清单。
- `receipt`：一次运行或发布的结果凭证，记录输入、输出、状态和检查结果。
- `campaign`：有明确目标、计划、多个步骤或多个 lane 的数据处理任务。
- `cutover`：将通过校验的新版本切换为正式 current 版本。
- `closeout`：确认任务已完成或正式终止，并冻结其后续处理决定。
- `retention`：关于保留、归档、复核和删除的生命周期策略。
- `entry rank`：候选筛选或策略比较使用的排名阈值，例如前 40 名或前 50 名。

## 历史名称处理

旧目录不因名称不符合规范而立即重命名。迁移顺序为：

1. 在 manifest 或 README 中注明规范名称和旧名称的对应关系；
2. 检查代码、服务、receipt 和报告中的引用；
3. 建立兼容 alias 或迁移后的稳定入口；
4. 更新消费者并验证；
5. 生成 retention 报告后，才考虑删除旧路径。

最后复核：`cache` 不代表一定可删除，`staging` 不代表一定是垃圾，`archive` 也不代表
永久保留。最终决定以生命周期状态、凭证和引用关系为准。
